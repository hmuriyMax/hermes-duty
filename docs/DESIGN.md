# Контракт P0 — «смотреть, ни на что не влияя»

Фаза P0 из дизайна (`~/.hermes/widgets/duty-model.html`, вкладка 07): собрать
видимость того, что происходит, **не меняя поведения** системы.

## Что P0 делает

1. Находит все живые kanban-БД (корневая = доска `default` + `kanban/boards/*/kanban.db`).
2. Открывает их строго на чтение (`?mode=ro`), собирает лизинги и последние события.
3. Показывает экран «сейчас»: дело, этап, кто держит (профиль, pid, ttl),
   последнее действие, возраст, и честную таксономию ожидания.

## Что P0 не делает никогда

- не пишет в `kanban.db`, `pool.db`, `state.db`;
- не импортирует диспетчер и не вызывает `hermes kanban`;
- не пересчитывает статусы карточек — только то, что записано;
- не запускает фоновых процессов и не заводит launchd-джоб.

## Источники

| источник | что берём |
|---|---|
| `<home>/kanban.db`, `<home>/kanban/boards/*/kanban.db` | `tasks` (лизинг, pid, статус), `task_runs` (попытки), `task_events` (журнал) |
| `<home>/messaging/pool.db` | `questions` — таксономия «ждёт человека» |
| `<home>/profiles/<role>/state.db` | сессии профилей (в v0.1 только перечисление) |

Пути не хардкодятся: корень вычисляется из `HERMES_HOME` или `~/.hermes`.

## Таксономия ожиданий (шесть состояний, взаимоисключающие)

| состояние | как определяется |
|---|---|
| `wait_human` | в пуле есть живой вопрос с `origin=card`/`session` для этого дела |
| `wait_gate` | у дела есть незавершённый родитель в графе зависимостей |
| `wait_slot` | статус `ready`/`todo`, но профиль уже занят другим делом |
| `dead_lease` | лизинг истёк, а процесс (pid) мёртв |
| `crashed` | `consecutive_failures >= limit` или последний ран `crashed`/`gave_up` |
| `capability` | блок с требованием прав/доступа |

Правило: состояние **не выводится из одной колонки**. Оно вычисляется по
набору фактов, и каждый факт показывается рядом как доказательство.

## Экраны

- **Сейчас** — список активных дел: `дело · этап | кто держит | последнее действие | возраст`.
- **Дело** — таймлайн попыток (данные из `task_runs` и `task_events`).
- **Почему стоит** — группировка по шести состояниям выше.
- **Здоровье** — доля этапов с первой попытки, медиана ожидания, таксономия отказов.

## Страница `/duty` (desktop)

Страница читает только два эндпоинта бэкенда — `GET /now` (раз в 10 с) и
`GET /duty/{board}/{task_id}/attempts` (по клику на дело); прямого `fetch`, шелла
и чтения файлов из UI нет. Ядро не импортируется, состояния не пересчитываются:
UI рисует `waiting.state` и `waiting.evidence` как есть, группируя строки в
порядке `wait_human > capability > dead_lease > crashed > working > wait_slot >
wait_gate`. Незнакомое состояние показывается последней группой серым, без
попытки его «доразобрать».

- строка таблицы: доска · `id` · title (многоточие) · assignee · возраст попытки ·
  состояние лизинга · возраст последнего действия · бейдж состояния с цветом
  (жёлтый `wait_human`, фиолетовый `capability`, красный `dead_lease`/`crashed`,
  зелёный `working`, серый `wait_slot`/`wait_gate`);
- фильтры локальные (доска, чипы состояний, поиск по `id`/title с debounce):
  `/now` на ввод не перезапрашивается;
- правая панель — таймлайн попыток: полоса на попытку относительно самой долгой,
  длительность, исход цветом, `error` текстом, события рана списком; пока
  грузится — скелетон;
- ошибка запроса — красная плашка с текстом и кнопкой «повторить», данные на
  экране не затираются; недоступные доски и упавшие источники (`errors`)
  показываются жёлтой полосой, а в пустом состоянии — списком
  «доска X недоступна: причина» рядом со счётчиком реально прочитанных досок.

Шейпер ответов — `desktop/model.js` (чистые функции, без React/DOM). Загрузчик
десктопных плагинов исполняет `plugin.js` как blob-модуль и отвергает любой
импорт вне `@hermes/plugin-sdk`/`react*`, включая относительные пути, поэтому
тело `model.js` вшито в `plugin.js` между маркерами `duty:model-start`/`duty:model-end`
(`bin/duty-model-sync`; расхождение ловит `tests/model.test.mjs`).

## Порядок работ

- `v0.0.1` — репозиторий, манифест, backend с `/health`, `/sources`, `/board/{slug}/tasks` (read-only),
  плюс `GET /now` (лизинги + таксономия ожиданий) и `GET /duty/{board}/{task_id}/attempts`.
- `v0.0.2` — сбор лизингов + экран «Сейчас» в dashboard (страница `/duty`).
- `v0.0.3` — таксономия ожиданий + экран «Почему стоит».
- `v0.0.4` — таймлайн попыток по `task_runs`/`task_events`.
- далее — P1 (`ask()` как единственный канал вопросов) уже в собственный журнал плагина.
